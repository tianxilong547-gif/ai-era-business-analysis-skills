# Clarify an analysis request

Create one analysis task brief with: decision, decision-maker, executor, object, metric, time window, comparison baseline, resource constraints, exclusions, deadline, and final deliverable.

## Workflow

1. Extract what is already known; do not re-ask it.
2. Separate the observed symptom from the decision to be made.
3. Rewrite the request as a falsifiable question with object, window, metric and baseline.
4. State the four report layers: current state, core problem, conditional trend, executable improvement.
5. List gaps internally, but ask at most one question—the one that materially changes scope or authorization.
6. If the decision can be reasonably inferred, proceed and label the assumption.

## Output and boundaries

Return the brief, rewritten question, assumptions, exclusions, and one prioritized confirmation item if truly required. Do not invent the decision, promise budget/timing, or proceed with personnel, legal, compliance, or external commitments without an authorized human. If there is no identifiable decision, label the work exploratory.

Use [test cases](references/test-cases.md) when validating changes.
